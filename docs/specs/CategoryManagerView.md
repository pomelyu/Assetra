# CategoryManagerView

資料欄位、計算規則與 Data API 依 [schema](../schema.md)。

## Purpose

管理用於 `AssetView` 與 `ReportView` 的資產分類名稱、順序與色彩。

## Information

- 列出所有分類、色彩、排序、引用該分類的帳戶數。
- 分類具有穩定識別；新資料庫的「未分類」需明確顯示為不可編輯，「存款」與「投資」的編輯能力與使用者建立的分類相同。

## Actions

- 新增分類；重新命名、變更色彩及調整排序，但「未分類」不提供重新命名、變更色彩或刪除操作。
- 刪除未被使用且非「未分類」的分類。
- 只要有封存帳戶使用該分類就不能刪除；不得透過分類重派修改封存帳戶。
- 僅有未封存帳戶使用時，刪除前必須選擇替代分類並原子性重新指派所有相關帳戶。

## Data and Rules

- 重新命名不得改變分類識別或任何歷史關聯。
- 分類只影響分組、排序與視覺映射，不改變帳戶的一般／股票／投資類型或會計規則。
- 分類名稱須在目前語言脈絡下可辨識且不可為空；色彩重複可以接受，但須保持圖例可辨識。
- 系統必須始終保留至少一個可指派分類。
- 新資料庫預設建立「未分類」、「存款」與「投資」三個分類。「存款」與「投資」可重新命名、變更色彩、排序與刪除；「未分類」為不可編輯的保留分類，不可刪除，但可參與排序並作為帳戶改派目標。

## States

- 沒有可顯示分類時顯示「尚未建立資料」；新資料庫正常會先有三個預設分類。
- 無法載入時提供重試，不允許在不完整資料上重新指派。
- 保存或重新指派失敗時整體回復，不得留下部分帳戶使用已刪除分類。

## Acceptance Criteria

- 名稱、色彩與順序變更會同步反映於資產篩選及報表。
- 「未分類」無編輯或刪除入口；「存款」與「投資」可依一般分類規則編輯。
- 任何帳戶都不會引用已刪除分類；有封存帳戶引用的分類刪除必須失敗且不改動任何帳戶。
- 分類修改不會改變資產金額或歷史快照內容。
